# 领域

本文件定义代码、UI 和文档中应保持稳定的产品术语。

## 参与方

- 当前用户：正在使用桌面端的已认证 Workshop 用户。
- Workshop 后端：项目、任务、用户和认证的远端事实源。
- 桌面客户端：展示个人任务工作面并存储本地个人记录的本地应用。
- Codex / 用户 AI：理解记录池、整理候选信息、执行代码任务并通过正式 bridge 回写结果的本地执行方；它不是项目事实源。

## 核心概念

- 本地项目：桌面端拥有的本机工作区。当前新建入口从本地目录开始创建，用于组织本地记录、本地目录绑定和 Codex 执行上下文，可选关联一个 Workshop 后端项目作为任务源。
- Workshop 项目：后端返回的远端项目。它聚合远端任务，并可以包含成员；在桌面端内只是可选任务源上下文，不是本地项目身份。
- 任务：外部任务系统返回的任务。当前实现主要来自 Workshop 后端任务，包含项目、内容、状态、创建者、可选执行者、时间戳和可选完成时间。
- 个人记录：桌面端存储的本地 markdown 记录。它可以是个人记录、项目记录或任务记录。
- 当前注意力工作台：Workshop Desktop 的产品定位。它帮助用户聚焦当前项目、任务、记录和确认动作，不承担完整知识库或完整项目管理系统职责。
- 工作台主页面：Dock、应用菜单、全局快捷键和首次启动流程打开的稳定应用主窗口。它承载本地项目、远端任务源状态、近期任务、记录入口和 Codex 运行状态。
- Workshop 账号：桌面端连接 Workshop 后端认证身份的账号状态。它由设置页登录或退出，不阻塞本地项目和本地记录使用。
- 远端任务源：登录后可同步的 Workshop 后端项目和任务来源；它只提供任务源上下文，不改变本地项目身份。
- 远端任务源关联：本地项目到一个 Workshop 项目的可选一对一关联。关联只用于读取和展示远端任务，不改变本地项目名称、记录归属或本地目录事实。
- 托盘面板：从菜单栏或系统托盘触发的轻量快速面板。它用于快速打开项目、记录和桌面便签，不承担完整主页面职责。
- 记录池：用户在 Workshop 中累积的个人、项目和任务记录集合。它是 Codex 可以理解、检索和整理的材料来源，但不是已接受事实层。
- 记录标注：附着在个人记录 metadata 上的 AI 整理索引。标注只保存标准化短字段，例如 `intent`、`retention`、`resolution`、`tags` 和关联对象 ID；不承载完整摘要，不改写记录正文，不改变记录是否显示在 Workshop 当前列表中。
- 便签窗口：轻量桌面浮动工作面。它可以常驻屏幕，展示一个项目的任务列表或单个任务详情；当前不是独立插件系统。
- 项目工作区：围绕某个本地项目打开的本地桌面工作面，通常由记录、目录和可选任务源组成。
- 项目本地目录：当前设备上绑定到本地项目的本地文件夹。它用于打开本机工作目录和后续 AI 执行上下文，不是 Workshop 后端项目字段；同一设备上一个目录只能绑定到一个本地项目。
- 本地 AI bridge：正在运行的桌面端提供的本机接口。Codex 或本地 CLI 可以通过它请求新增记录、打开记录、把任务或记录发送给 Codex 执行等应用动作。
- 当前上下文：桌面端最近获得焦点的 Workshop 对象，例如工作台主页面、托盘面板、项目任务面、单个任务、项目记录、任务记录或记录草稿。它帮助 Codex 理解“这条记录”“当前任务”等对话指代。
- Codex 运行：一次发送到 Codex 的执行遥测（后端、线程、状态、最后消息）。它是运行时状态，不是记录或任务，不参与晋升流程。
- 临时确认页面：由本地 AI/CLI 提供 HTML，Workshop Desktop 在独立窗口中渲染，并由用户确认或取消的一次性操作面。它用于确认批量整理等高风险写入方案，本身不是记录、任务或项目事实。
- 异步确认请求：临时确认页面的一种运行状态。调用方提交确认页面和受限动作后立即获得 `requestId`；用户确认后，由 Workshop 自己执行该动作并记录最终状态。

## 任务状态

当前共享任务状态是：

- `pending`
- `in_progress`
- `pending_review`
- `completed`
- `accepted`
- `cancelled`
- `blocked`

桌面端 UI 支持轻量状态操作：开始、完成、阻塞、退回待办。

## 个人记录范围

- `none`：不绑定项目或任务的个人记录。
- `project`：项目记录。一个本地项目可以有多条 active 记录；旧数据中也可能暂时关联 Workshop 后端项目 ID。
- `task`：任务记录。每个任务最多有一条 active 任务记录。

## 个人记录状态

- `active`：显示在 active 记录列表中。
- `completed`：作为本地记录完成，仍显示在记录列表中。
- `promoted`：已经转成 Workshop 任务，从记录列表隐藏。
- `archived`：从记录列表隐藏。

## 个人记录来源

- `human`（缺省，历史记录视为 human）：用户在桌面端创建的记录，是人类思考载体。
- `agent`：通过本地 AI bridge 创建的记录，是机器产物（执行结果、AI 沉淀）。

来源跟随创建者，编辑不改变来源。它用于区分人类思考与机器报告；agent 记录在晋升为任务或 repo 事实前同样需要人工确认。

## 晋升边界

个人记录默认是思考和执行材料，不是项目事实。只有当记录被转成外部任务，或被人工整理为已接受的 repo 文档后，才进入正式执行或事实层。

Repo 文档是独立层。除非经过晋升和审查，不要把本地个人记录当作已接受的架构、需求或决策。

本地 AI bridge 写入的是应用记录，不是 repo 文档。AI 写入的记录需要用户或后续流程审查后，才能进一步晋升为任务或 repo 事实。

发送到 Codex 是执行动作，不是新的任务、记录或决策类型。任务仍归属 Workshop 任务体系；记录仍归属本地个人记录体系；Codex 只接收当前对象内容和项目本地目录作为执行上下文。

Codex 可以理解、检索、整理记录池，生成候选变更并执行代码任务；最终事实写入必须通过 Workshop 确认页、Workshop 任务体系或 repo 文档审查完成。

## 记录整理标注

归档记录默认不再进入 Workshop 当前关注列表。Codex 可以读取归档记录并生成整理标注；经用户确认后，Workshop 通过正式 app server 通道写入标注。

记录正文是唯一叙事源。AI 需要补充可读信息时，应通过正文追加或改写表达，例如追加执行结果、结论、风险和后续建议；这类写入必须经过用户确认，并由 Workshop 在确认后执行。

标注用于 Codex 后续检索、分类、聚合和对话，不要求 Workshop UI 默认展示类型或筛选器。标注字段应保持简洁、标准化和可重算；分类变化时优先重跑标注，不迁移记录正文。

修改原始正文、创建任务或批量改变状态属于更高风险动作，需要通过临时确认页面明确展示变更范围。删除、合并和重组多条记录暂不作为默认自动动作。

当记录数量增长时，默认优先增强检索、标注、关联和确认流程；不要为了整理方便就把记录升级成复杂固定类型系统。
