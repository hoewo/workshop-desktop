# Workshop Desktop · 功能清单（用户视角）

> 这份清单描述的是：打开 Workshop Desktop 后，**你能做什么、每个功能对你有什么用**。
> 每项标注是否属于 MVP 第一版（基于 [decisions.md](decisions/decisions.md) 边界审查）。

---

## 一、记录池（你的核心工作区）

记录池是 Workshop 打开后的主区域。你在日常工作中产生的思考、结论、上下文，都以"记录"的形式存在这里。

| 功能 | 说明 | MVP |
|---|---|---|
| **查看记录列表** | 主区域展示所有记录，每条显示标题、摘要、来源（人记/机器记）、归属（项目/个人）、时间和标注。这是你回顾"之前想过什么"的入口 | ✅ |
| **新建记录** | 点"+ 新建"打开表单，填写标题和正文。你可以选择这条记录归属"项目"还是"个人"，以及挂到哪个项目下。正文默认写短记录（3-6 行：结论 / 影响 / 下一步） | ✅ |
| **查看记录详情** | 点任意记录打开详情弹层，看完整正文、来源、归属、标注和时间。如果这条记录是 AI 回写的，会额外标注"这是 Agent 被注入记录后回写的结果" | ✅ |
| **按来源筛选** | 筛选"全部 / 人记 / 机器记"。用来区分哪些是你自己写的思考，哪些是 AI 执行后自动回写的结论 | ✅ |
| **按归属筛选** | 筛选"全部 / 项目 / 个人"。项目记录挂靠到具体项目目录，个人记录不绑定项目 | ✅ |
| **按标注筛选** | 记录带 intent（意图）和 resolution（状态）标注，可在列表中看到。"只看被取用"可筛出被 AI 用过的记录 | 部分（基础标注 ✅，"只看被取用"后续） |

---

## 二、项目（记录的切片维度）

项目是组织记录的方式。每个项目绑定一个本地目录，目录路径同时是 AI 执行任务时的工作目录（cwd）。

| 功能 | 说明 | MVP |
|---|---|---|
| **查看项目列表** | 左侧栏列出所有已绑定的项目，点击切换记录池只显示该项目的记录 | ✅ |
| **绑定项目目录** | 点"+ 绑定目录"，填写项目名并选择本地文件夹。绑定后，这个目录成为 AI 执行任务时的落点，记录按项目切片 | ✅ |

---

## 三、记录便签（随手快记）

便签是一个可以随时打开的小窗口，浮在所有窗口上层。你在工作中突然想到什么，不用切到主窗口，直接在便签里写下来。

| 功能 | 说明 | MVP |
|---|---|---|
| **打开/关闭便签** | 顶栏点 ✎ 打开便签；点 ✕ 关闭。关闭时自动清空输入框、复位位置 | ✅ |
| **拖拽便签** | 按住便签标题栏，可以把便签拖到屏幕上任意位置，不遮挡当前工作区 | ✅ |
| **折叠便签** | 点 ▾ 按钮，便签只留标题栏，收起内容区域；再点展开。适合暂时不用但不想关闭的场景 | ✅ |
| **切换便签归属** | 便签内可切换"项目 / 个人"和具体项目，决定这条便签记到哪里 | ✅ |
| **快速记下** | 在便签输入框写完，点"记下"即保存为一条记录。第一行作为标题，后续作为正文 | ✅ |
| **查看最近便签** | 便签下方列出最近 6 条人记记录，点开可看详情 | ✅ |

## 四、AI 协作（记录与编程工具的闭环）

Workshop 的核心价值不只是记笔记——它让记录真正影响 AI 的执行。当你把记录发送给 Codex 时，记录池的上下文会被注入到 AI 的执行过程中。

| 功能 | 说明 | MVP |
|---|---|---|
| **Codex 运行状态** | 顶部一行状态条显示 Codex 当前状态（空闲/运行中）、最后一次运行的信息。不占主区域，只在需要时瞥一眼 | ✅ |
| **发送记录到 Codex** | 从记录或任务触发"发送到 Codex"时，Workshop 把当前记录的内容塞进 Codex 的 prompt，Codex 在对应项目目录下执行任务 | ✅（注入逻辑待补：当前 `buildCodexUserInput` 零注入，只塞 body/title，不查历史相关记录） |
| **AI 回写记录** | Codex 执行完成后，结论会自动写回记录池，标记为"机器记"（origin=agent）。你在列表里能区分哪些是自己写的、哪些是 AI 回写的 | ✅ |

## 五、AI 遥测面板（看 AI 怎么用了你的记录）

这个面板让你看到 AI 到底用了你的哪些记录、查了什么。它是验证"记录是否真的帮助了后续任务"的窗口。

| 功能 | 说明 | MVP |
|---|---|---|
| **打开遥测面板** | 顶栏点"遥测"按钮展开下拉面板 | 后续 |
| **注入命中记录** | "注入命中"tab：展示每次 Codex 运行时被注入了哪些记录、触发了什么任务、回写了什么结论。你可以点开每条被注入的记录看详情 | 后续 |
| **取用记录** | "取用"tab：展示编程工具在执行任务前主动检索了哪些记录、查了什么关键词、命中了哪些。每条标注协议来源（RPC/MCP） | 后续 |
| **安全模型说明** | 面板底部说明读开放（AI 能搜能读）和写收紧（AI 只能新增记录，改写需你确认）的边界 | 后续 |

> 遥测数据源（`codex-runs/index.json`、`record-searches/index.json`）已在代码中写入，UI 展示是 dogfood 验证阶段的增强。

## 附：MVP 边界说明

**第一版聚焦"记录能写、能看、能被 AI 用"：**

| 分类 | MVP 第一版 | 后续阶段 |
|---|---|---|
| **记录池** | 记录列表、新建、详情、来源筛选、归属筛选 | — |
| **项目** | 项目列表、绑定目录 | — |
| **便签** | 打开/关闭、拖拽、折叠、快记、归属切换、最近列表 | — |
| **AI 协作** | Codex 运行状态、发送记录、AI 回写 | — |
| **AI 遥测面板** | — | 注入命中时间线、取用时间线、安全说明 |
| **设置** | — | 脱敏规则配置 |
| **标注筛选** | 基础标注展示 | "只看被取用"筛选 |

**当前 MVP 缺口（需补齐才构成完整闭环）：**

1. **origin UI 展示** — 数据层完整（agent 创建即标 agent，不可被人类编辑覆盖），但记录列表/详情中用户看不到 origin 标识
2. **buildCodexUserInput 零注入** — 注入路径能力存在但没接好，只塞当前记录 body/title，不查历史相关记录
